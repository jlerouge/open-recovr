# Contributing to Open Recovr

Thanks for wanting to help! Bug reports, translations, documentation and code are all welcome.

## Ground rules

- **Be kind.** Many users arrive here after losing precious files, so treat their reports with care.
- **Never write to the drive being searched.** This is the project's core promise. Any change that could write to the source drive will be refused.
- **Keep it simple for non-technical people.** The main screen must stay usable by someone who has never heard of "carving" or "MFT". Advanced things go in expert mode.

## Reporting a bug

Open an [issue](https://github.com/jlerouge/open-recovr/issues) with:

- your system (Windows 10/11, distribution, macOS version) and the Open Recovr version;
- the kind of drive (hard disk, SSD, SD card, USB stick…) and its file system if you know it;
- what you did, what you expected and what happened;
- if possible, the **search log**. Turn on *Expert mode*, run the search again, then click *Copy all*.

Do not attach recovered files or disk images that may contain personal data.

## Building

You need [Rust](https://rustup.rs) 1.95 or newer.

```sh
git clone https://github.com/jlerouge/open-recovr
cd open-recovr
cargo run --release
```

**Windows:** the deep search needs PhotoRec. It is not stored in Git, so fetch it once:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\fetch-photorec.ps1
```

The script downloads the official TestDisk 7.2 archive from cgsecurity.org. It keeps only `photorec_win.exe`, its Cygwin DLLs and the licence files, and checks each one against a known SHA-256.

**Linux:** install the window libraries and PhotoRec:

```sh
sudo apt install libxkbcommon-dev libwayland-dev libxcb-render0-dev libxcb-shape0-dev libxcb-xfixes0-dev testdisk
```

**macOS:** `brew install testdisk`.

## Before sending a pull request

CI runs these three commands on Windows, Linux and macOS. Run them locally first:

```sh
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test -- --skip tray_icon_comes_and_goes
```

(`tray_icon_comes_and_goes` needs a real desktop session, so CI skips it.)

`cargo run --release -- --bench` checks recovery quality without touching a real drive. It builds a 256 MB disk image with known files, deletes them, then measures how many files each search method brings back byte for byte.

Keep pull requests focused: one fix or feature per PR. Explain *why* in the description. Add a line to [CHANGELOG.md](CHANGELOG.md) for anything a user would notice.

## Code layout

See [docs/architecture.md](docs/architecture.md) for a tour of the modules. In short:

- `src/app.rs` holds the single screen;
- `src/engine.rs` holds the background work;
- `src/ntfs.rs`, `src/carve.rs` and `src/photorec.rs` are the three ways of finding files;
- `src/sys/` holds the code specific to each operating system.

Code comments are written in plain English and say *why*, not *what*.

## Translating

Interface texts are written in French in the code, inside `t!("…")`. Each other language has a file in `lang/`: the French line, then `= its translation` just below it.

- **To fix a translation**, edit the right file in `lang/`.
- **To add a language**, copy `lang/en.txt` to `lang/xx.txt` and translate every `=` line. Then register the language in `src/i18n.rs`.

The `every_language_has_every_text` test reports any missing text. Translating the READMEs (`README.xx.md`) is welcome too.

## Screenshots

The screenshots in `docs/screenshots/` are generated by the app itself, so they stay reproducible. `--screenshot file.png` draws the window off-screen, saves it and quits. `--scene` picks the moment to show: `home`, `scanning`, `selected` or `recovered`.

```sh
cargo build --release
scripts/screenshots.sh C     # drive letter or mount point to show
```

This regenerates the 7 phases in the 4 languages. The quick search lists what is in the Recycle Bin, so put a few harmless demo files there first.

## Releasing

For the maintainer. Open Recovr only installs an update whose `SHA256SUMS.txt` is signed with the key in [`keys/open-recovr.pub`](keys/README.md), and the secret half of that key stays off GitHub. So a release takes one step by hand:

You need [minisign](https://jedisct1.github.io/minisign/) (`winget install jedisct1.minisign`) and the secret key, kept as [keys/README.md](keys/README.md) says.

1. **Version.** Set the version in `Cargo.toml` and move the `Unreleased` part of `CHANGELOG.md` under it. Commit, then tag and push: `git tag v0.3.0 && git push origin main v0.3.0`.
2. **Draft.** The release workflow builds everything and makes a **draft** release; it appears only once every build is done, Windows being the slowest. Nobody sees the draft yet, and the updater ignores it. Until it is published, its address is `…/releases/tag/untagged-…`, not `…/tag/v0.3.0`; you find it at the top of the Releases page.
3. **Try it.** From the draft's *Assets*, download `SHA256SUMS.txt` and the `…-setup.exe` into your Downloads folder. Check that the setup's SHA-256 is the one in `SHA256SUMS.txt`, then install it: Windows SmartScreen warns about an unknown publisher, so choose *More info*, then *Run anyway*. No administrator rights should be asked. The app starts with the new version in its footer and has a Start menu entry. Uninstalling it works.
4. **Sign.** From the repository folder, run:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\sign-release.ps1 -Tag v0.3.0
   ```

   It checks three things:
   - GitHub's tag points to your commit;
   - `~\Downloads\SHA256SUMS.txt` is this version's;
   - the signature checks out.

   It signs in between. minisign asks for the key's password, and nothing shows while you type it. The script writes `SHA256SUMS.txt.minisig` next to the checksums, and should end with "Signature and comment signature verified" and `Trusted comment: open-recovr v0.3.0`.
5. **Attach and publish.** On the draft, click the pencil icon. Drop `SHA256SUMS.txt.minisig` onto *Attach binaries*, then click *Publish release*.
6. **Check.** Download both files again from `…/releases/latest/download/` and run `minisign -V -p keys/open-recovr.pub -m SHA256SUMS.txt`.
7. **Try the update.** A debug build can pretend to be older. Copy `target/debug/open-recovr.exe` (from `cargo build`) into an empty folder, then run it with `--pretend-version 0.2.9`. The footer offers the new version. One click downloads it, checks it, installs it over the copy and relaunches it.

A release published without its `.minisig` is not dangerous: Open Recovr refuses to install it and says why. Add the file and the update goes through. Versions before 0.3.0 have no updater: their users download the new version by hand once.

## Use of AI tools

**Generative AI is welcome.** The first version of Open Recovr was itself built with AI assistance. You can use Copilot, Claude, ChatGPT or any other tool to write code, tests, docs or translations, on these conditions:

- **You are the author.** You have read, understood and tested what you submit, and you can explain it in review.
- **Say so** in the PR description when a significant part was generated (one line is enough, e.g. "tests drafted with Claude").
- **Check the licence.** Don't submit generated code that obviously reproduces existing code under an incompatible licence.
- **Have a human review machine translations**, ideally a native speaker, before you submit them.
